## 1. 문제

요플레 공장을 N주 동안 운영해야 한다. i번째 주에는 우유가 `Y[i]`ℓ 필요하고, 그 주에 우유를 사면 1ℓ당 `C[i]`원이다.
우유는 창고에 무제한으로 보관할 수 있고, 1ℓ를 1주 보관하는 데 `S`원이 든다. (N주 동안 보관 가능)

N주를 운영하는 데 드는 최소 비용을 구한다.

### 입력

```
첫 줄              N S
둘째 줄 ~ N+1째 줄   C[i] Y[i]   (1주부터 순서대로)
```

### 출력

N주 동안 공장을 운영하는 최소 비용. **답이 매우 클 수 있으니 유의.**

### 제한

- `1 ≤ N ≤ 100,000`
- `1 ≤ S ≤ 100`
- `1 ≤ C[i] ≤ 5,000`
- `0 ≤ Y[i] ≤ 10,000`
- 시간 1초 / 메모리 32MB

### 예제

```
[입력]
4 5
88 200
89 400
97 300
91 500

[출력]
126900
```

## 2. 접근

### 관찰

- i주에 쓸 우유는 **i주에 사거나, i보다 앞선 j주에 사서 (i-j)주 보관해 온 것**이다. 미래 가격을 미리 끌어다 쓸 수는 없다.
- j주에 사서 i주에 쓰면 1ℓ당 `C[j] + (i-j) * S`원. 즉 **살 때 싸도 오래 들고 있으면 보관비가 붙어 비싸진다.**
- 각 주의 필요량 `Y[i]`는 서로 독립이다. i주에 몇 ℓ를 사든 다른 주에 영향을 주지 않으므로, **주마다 1ℓ 단가를 최소로 만들면 전체 합도 최소**가 된다.
- 정리하면 i주의 최소 단가는 `best[i] = min(C[j] + (i-j) * S)` (단, `j ≤ i`), 답은 `Σ best[i] * Y[i]`.

### 아이디어

`best[i]`를 구하려고 매번 j를 1부터 i까지 훑으면 O(N^2)이라 N=100,000에서 터진다.

그런데 후보를 전부 볼 필요가 없다. **"지금까지 가장 싸게 사둔 주" 하나만 `day`에 들고 다니면 된다.**
i주에 도착했을 때 선택지는 둘뿐이다 — `day`주에서 사서 들고 온 것(`C[day] + (i-day)*S`)과 이번 주 현지가(`C[i]`).
현지가가 더 싸면 그 주가 새로운 최저가 기준이 되므로 `day = i`로 갈아끼운다.

이게 정당한 이유는 `best[i] = min(C[i], best[i-1] + S)`이기 때문이다.
`day`가 `best[i-1]`을 만든 주라면 `C[day] + (i-day)*S`가 곧 `best[i-1] + S`이므로, 두 값만 비교하면 최소가 유지된다.
그래서 갱신이 O(1)이고 전체가 한 번의 스위핑으로 끝난다.

비용은 `dp[i] = dp[i-1] + (그 주 단가) * Y[i]`로 왼쪽부터 누적한다.

### 알고리즘 선택

| 후보 | 가능 여부 | 채택 |
| --- | --- | --- |
| 모든 (구매 주 j, 사용 주 i) 쌍 비교 | O(N^2) = 10^10 → 1초 초과 | X |
| 최저가 주 포인터 하나로 스위핑 | O(N) = 10^5 | **O** |
| 우선순위 큐로 최저가 관리 | 가능하지만 O(N log N), 후보가 2개뿐이라 과함 | X |

## 3. 설계

### 동작 순서

```
1. N, S 입력
2. cArr[1..N], yArr[1..N] 입력받아 저장
3. day = 1                       // 지금까지 가장 싸게 살 수 있는 주
4. i = 1..N 반복:
   4-1. 보관해서 가져온 단가 carried = cArr[day] + (i-day) * S
   4-2. carried <= cArr[i] 이면 → 그 단가로 산다
        아니면              → day = i 로 갱신하고 cArr[i] 단가로 산다
   4-3. dp[i] = (선택한 단가) * yArr[i] + dp[i-1]
5. dp[N] 출력
```

`i == day`인 첫 주에는 `(i-day) = 0`이라 조건이 `C[i] <= C[i]`가 되어 자연스럽게 참이 되고, 초기화를 따로 할 필요가 없다.

### 엣지 케이스

- **`Y[i] == 0`인 주** — 그 주 비용은 0이지만 **가격 갱신은 그대로 일어나야 한다.** 그 주가 쌌다면 이후 주에서 그 가격으로 사올 수 있기 때문이다. 현재 코드는 `Y`와 무관하게 `day`를 갱신하므로 문제없다.
- **답이 int를 넘는다** — 최대 `5,000 × 10,000 × 100,000 = 5 × 10^12`. `dp`를 `long`으로 둔 게 핵심. 문제에서 "답이 매우 클 수 있으니 유의"라고 경고한 부분이다.
- **`N == 1`** — 위 첫 주 처리로 그대로 커버된다.
- **비교의 등호(`<=`)** — 두 단가가 같을 때 어느 쪽을 잡아도 이후 단가가 동일하므로 결과가 바뀌지 않는다.

## 4. 복잡도

| 구분 | 복잡도 | 근거 |
| --- | --- | --- |
| 시간 | O(N) | 주마다 비교 1번 + 곱셈 1번. N ≤ 100,000이라 약 10^5 연산 → 1초 제한에 여유 |
| 공간 | O(N) | `int[N+1]` 2개 + `long[N+1]` 1개 = 약 1.6MB → 32MB 제한 안 |

**답의 크기 추정**: 단가는 최대 5,000원 근처, 총 필요량은 `10,000 × 100,000 = 10^9`ℓ.
곱하면 약 `5 × 10^12`로 int 한계(약 `2 × 10^9`)를 3자리 넘는다 → **`long` 필수**.

## 5. 코드

```java
import java.io.*;
import java.util.*;

public class Main {

    static int MAX = Integer.MIN_VALUE;
    static boolean[] visited;
    public static void main(String[] args) throws Exception{

        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));

        StringTokenizer st = new StringTokenizer(br.readLine());

        int N = Integer.parseInt(st.nextToken());    // 주
        int S = Integer.parseInt(st.nextToken());    // 1주 보관에 필요한 비용

        int[] cArr = new int[N+1];
        int[] yArr = new int[N+1];
        for (int i = 1; i <= N; i++) {
            st = new StringTokenizer(br.readLine());

            cArr[i] = Integer.parseInt(st.nextToken());
            yArr[i] = Integer.parseInt(st.nextToken());
        }

        long[] dp = new long[N+1];
        int day = 1;
        for (int i = 1; i <= N; i++) {

            if (cArr[day] + (i-day) * S <= cArr[i]) {
                dp[i] = (cArr[day] + (i-day) * S) * yArr[i] + dp[i-1];

            } else {
                day = i;
                dp[i] = cArr[day] * yArr[i] + dp[i-1];
            }


        }

        System.out.println(dp[N]);
    }

}
```

## 8. 배운 것

**"과거에서만 자원을 끌어올 수 있고, 시간이 지날수록 유지비가 붙는" 비용 문제는 O(N) 스위핑 그리디로 풀린다.**
매 시점의 최소 단가를 `best = min(현재가, 직전 best + 유지비)` 한 줄로 갱신하면, 모든 과거 후보를 다시 볼 필요가 없다.

곁들여 얻은 것 두 가지:

- **각 시점의 수요가 서로 독립이면 문제를 쪼갤 수 있다.** "시점별 최소 단가 × 그 시점 수요"의 합이 곧 전체 최솟값이다. 이 분리가 성립하는지 먼저 확인하면 풀이가 단순해진다.
- **답의 최댓값을 손으로 곱해보고 `long`을 결정하는 습관.** 여기선 문제가 대놓고 경고해줬지만, 안 해주는 문제가 더 많다.
