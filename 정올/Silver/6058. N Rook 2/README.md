## 1. 문제

`N × N` 체스판이 주어진다. 칸은 `.`(빈칸) 또는 `#`(장애물)이고, `#`에는 rook을 놓을 수 없다.
rook은 가로·세로로 움직이므로 **같은 행이나 같은 열에 두 개가 있으면 서로 잡는다.**
그런 일이 없도록 rook `N`개를 놓는 방법의 수를 구한다.

> **함정**: `#`을 사이에 두고 놓아도 서로 잡을 수 있다. 즉 **장애물은 공격을 막지 못한다.**
> 장애물의 역할은 오직 "그 칸에 못 놓는다" 하나뿐이다.

### 입력

```
첫 줄              N            (rook의 수 = 체스판 한 변의 길이)
둘째 줄 ~ N+1째 줄   N개의 문자   ('.' 또는 '#')
```

### 출력

서로 잡지 않도록 `N`개의 rook을 놓는 방법의 수.

### 제한

- `1 ≤ N ≤ 9`
- 시간 1초 / 메모리 1024MB

### 예제

```
[입력]
3
...
...
...

[출력]
6
```

```
[입력]
5
.####
....#
.....
#.###
.##..

[출력]
3
```

## 2. 접근

### 관찰

- **rook은 정확히 `N`개, 행도 `N`개다.** 한 행에 두 개를 놓으면 그 둘이 서로 잡으므로, **모든 행에 정확히 하나씩** 들어가야 한다. 열도 마찬가지.
- 그러면 답은 결국 **"행 → 열"의 순열 개수**다. `i`번 행의 rook이 놓인 열을 `p[i]`라 하면 `p`는 `0..N-1`의 순열이고, 장애물 조건은 `map[i][p[i]] != '#'`.
- 장애물이 없으면 답은 그냥 `N!`이다. 예제 1의 `N=3` → `3! = 6`이 정확히 이 값이다.
- **`#`이 공격을 막지 않는다**는 조건 덕분에 문제가 훨씬 쉬워진다. 만약 막았다면 "행 하나에 rook 하나"가 깨져서(장애물로 갈라진 구간마다 하나씩) 이분매칭 같은 게 필요했을 것이다. 여기선 열 하나만 관리하면 된다.
- `N ≤ 9`라 최악이 `9! = 362,880`. 전부 세도 된다.

### 아이디어

행을 위에서부터 하나씩 내려가면서 **"이 행의 rook을 몇 번 열에 놓을까"**만 정하면 된다.
행은 재귀 깊이가 알아서 하나씩 소비하므로 행 중복은 구조적으로 불가능하고, **열 중복만 `boolean[] cols`로 막으면** 된다.

`r`행에서 아직 안 쓴 열 `c`이고 `map[r][c]`가 장애물이 아니면 그 칸을 골라 `cols[c] = true`로 잠그고 `r+1`행으로 내려간다.
돌아오면 `cols[c] = false`로 풀어서(백트래킹) 다음 후보를 시도한다.
`N`개를 다 놓으면 순열 하나가 완성된 것이므로 `ans++`.

중간에 놓을 칸이 없으면 for문이 그냥 끝나고 자동으로 되돌아가므로, 실패 처리를 따로 쓸 필요가 없다.

### 알고리즘 선택

| 후보 | 가능 여부 | 채택 |
| --- | --- | --- |
| 모든 칸에서 `N`개 조합 선택 후 검사 | `C(81, 9) ≈ 2.6 × 10^11` → 불가능 | X |
| 행마다 열을 고르는 백트래킹 | 최악 `9! = 362,880` | **O** |
| 비트마스크 DP (`dp[행][열 사용 마스크]`) | `9 × 2^9`으로 더 빠름 | X: 이 크기엔 과함 |

**자료구조**: 열 사용 여부는 `boolean[N]` 하나면 충분하다. `Set`을 쓰면 해싱 비용만 늘고 인덱스가 `0..N-1`로 이미 조밀해서 이득이 없다.

## 3. 설계

### 동작 순서

```
1. N 입력, map[N][N] 입력
2. dfs(r = 0, cols = 전부 false, nRook = 0) 호출
3. dfs(r, cols, nRook):
   3-1. nRook == N 이면 → ans++ 하고 리턴 (N개를 다 놓음)
   3-2. c = 0..N-1 반복:
        - cols[c]가 true(열 이미 사용) 이거나 map[r][c] == '#' 이면 건너뜀
        - cols[c] = true
        - dfs(r+1, cols, nRook+1)
        - cols[c] = false        // 원상복구
4. ans 출력
```

`cols`는 새로 만들지 않고 **같은 배열을 계속 넘긴다.** 대신 재귀에서 돌아온 직후 반드시 `false`로 되돌려야 한다.
이 복구를 빼먹으면 한 번 쓴 열이 영원히 잠겨서 답이 크게 줄어든다.

### 엣지 케이스

- **`N == 1`이고 칸이 `#`** — 첫 행에서 놓을 칸이 없어 for문이 그냥 끝나고 `ans = 0`. 검증 완료.
- **`N == 1`이고 칸이 `.`** — `ans = 1`. 검증 완료.
- **답이 0인 경우** — 예: 한 행이 전부 `#`이면 그 행에 놓을 수 없으므로 답이 0. 별도 처리 없이 자연히 0이 나온다.
- **`#`이 공격을 막는다고 오해** — 이게 이 문제의 유일한 함정. 막는다고 풀면 예제 2에서 답이 달라진다.
- **`ans` 자료형** — 최대 `9! = 362,880`이라 `int`로 충분하다.

## 4. 복잡도

| 구분 | 복잡도 | 근거 |
| --- | --- | --- |
| 시간 | O(N!) | 호출 수는 부분순열의 개수 `Σ P(N,k)`. `N=9`면 986,410개, 각 호출이 열 `N`개를 훑으므로 약 `9 × 10^6` 연산 → 1초 안에 충분 |
| 공간 | O(N^2) | `map[9][9]` + `boolean[9]` + 재귀 깊이 `N`. 1024MB 제한에 무의미한 수준 |

`N`이 9로 못 박혀 있다는 게 핵심이다. `9! = 362,880`은 완전탐색이 허용되는 크기이고,
장애물이 있으면 가지치기로 더 줄어들기만 하므로 최악은 **판이 전부 `.`일 때**다.
실제로 9×9 전부 `.`로 돌려보니 **0.18초**에 `362880`이 나왔다.

## 5. 코드

```java
import java.io.*;
import java.util.*;

public class Main {
    
    static String[][] map;
    static int N, ans;
    public static void main(String[] args) throws Exception{
        
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        
        
        N = Integer.parseInt(br.readLine());
        map = new String[N][N];
        
        for (int r = 0; r < N; r++) {
            map[r] = br.readLine().split("");
        }
        
        /*
         * 문제 조건
         * - '.'은 빈칸, '#'은 장애물
         * - 체스 rook은 가로 세로에 있는 다른 말을 잡을 수 있다
         * - 체스판에 N개의 rook들을 배치할 때 서로 잡을 수 없게 배치하는 경우의 수를 출력한다. 
         * - N은 1~9 사이의 정수
         * 
         * 계획 1 (dfs)
         * - 0번째 행부터 N번째 행까지 rook을 배치함
         * - 길이가 N인 boolean 배열을 둠
         * - 재귀 함수를 이용해서 i번째 열에 rook을 배치하고 boolean 배열의 i 인덱스를 true로 변경
         * - 다음 함수 호출에 해당 배열 넘김 
         * - 배치한 rook의 수가 N과 같아지면 ans 증가
         * 
         */
        
        
        dfs(0, new boolean[N] , 0);
        
        System.out.println(ans);
    } 
    
    static void dfs(int r, boolean[] cols, int nRook) {
        
        // 모든 rook을 배치한 경우 리턴
        if (nRook == N) {
            ans++;
            return;
        }
        
        for (int c = 0; c < N; c++) {
            // 이미 한개의 rook이 배치된 열이면 건너뜀
            if (cols[c]||map[r][c].equals("#")) continue;
            
            cols[c] = true;
            dfs(r+1, cols, nRook+1);
            cols[c] = false;
        }
    }
    
}
```

## 7. 개선할 점

**1. `nRook` 파라미터는 `r`과 항상 같다**

```java
dfs(r+1, cols, nRook+1);   // r과 nRook이 늘 같이 1씩 증가
```

시작이 `(0, 0)`이고 언제나 함께 `+1`이므로 `nRook == r`이 항상 성립한다. 종료 조건을 `if (r == N)`으로 바꾸면 파라미터 하나를 통째로 지울 수 있다.
"몇 개 놓았는지"와 "몇 번째 행인지"가 같은 값이라는 건 곧 **모든 행에 정확히 하나씩 놓는다**는 이 문제의 성질 그 자체다. 파라미터를 지우면 그 성질이 코드에 더 잘 드러난다.

**2. `String[][]` 대신 `char[][]`**

```java
map[r] = br.readLine().split("");     // 행마다 String 객체 N개 생성
if (map[r][c].equals("#")) ...        // 매 비교마다 메서드 호출
```

→

```java
map[r] = br.readLine().toCharArray();
if (map[r][c] == '#') ...             // 원시 타입 비교
```

`split("")`은 정규식 엔진을 거쳐 `String` 배열을 새로 만든다. `N ≤ 9`라 여기선 티가 안 나지만, 격자 크기가 큰 문제에선 이 습관 하나로 시간 초과가 갈린다. 격자 입력은 `toCharArray()`가 기본값이라고 생각하자.

**3. `boolean[]`을 넘기지 말고 `int` 비트마스크로**

`cols`는 백트래킹으로 복구되므로 사실상 전역 상태다. 매 호출에 참조를 넘길 이유가 없다.

```java
static void dfs(int r, int used) {
    if (r == N) { ans++; return; }
    for (int c = 0; c < N; c++) {
        if ((used & (1 << c)) != 0 || map[r][c] == '#') continue;
        dfs(r + 1, used | (1 << c));
    }
}
```

`int` 하나가 값으로 복사되므로 **복구 코드(`cols[c] = false`)가 아예 필요 없어진다.** 백트래킹에서 복구를 빼먹는 실수를 구조적으로 없애는 방법이다.

**4. 더 나아가면 비트마스크 DP**

`dp[열 사용 마스크] = 그 마스크를 만드는 경우의 수`로 두면 `O(N × 2^N)`, `N=9`에서 4,608번이면 끝난다. 지금 크기엔 필요 없지만 `N`이 15~20까지 커지면 이게 정답이 된다.

## 8. 배운 것

**"각 행에 정확히 하나, 각 열에 정확히 하나"는 곧 순열이다. 그러면 재귀 깊이로 행을 소비하고 열만 체크하면 된다.**

`N`개의 말을 `N × N`판에 행·열 충돌 없이 놓는 문제는 전부 이 형태다. 행 중복은 "한 깊이에서 한 칸만 고른다"는 구조가 공짜로 막아주므로, **중복 체크는 열 하나만** 하면 된다. 여기서 대각선까지 막으면 그대로 N-Queens가 된다.

곁들여 얻은 것 두 가지:

- **장애물이 "못 놓는 칸"인지 "공격을 막는 벽"인지 반드시 확인한다.** 이 문제는 전자라서 순열 세기로 끝나지만, 후자였다면 한 행에 rook이 여러 개 들어갈 수 있어 완전히 다른 문제(이분매칭 계열)가 된다. 한 줄 차이로 난이도가 갈린다.
- **입력 상한을 먼저 계승/거듭제곱에 대입해보고 완전탐색 여부를 판단한다.** `N ≤ 9` → `9! ≈ 3.6 × 10^5`. 이 계산 한 번이면 "백트래킹으로 그냥 다 세면 된다"는 결론이 즉시 나오고, 더 영리한 풀이를 고민하는 시간을 아낄 수 있다.
